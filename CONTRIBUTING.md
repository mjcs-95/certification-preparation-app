# Contributing to CertifyLab

Thank you for considering contributing to CertifyLab.

Bug reports, feature proposals, documentation improvements, tests, and code contributions are welcome.

## Development workflow

1. Fork the repository.
2. Create a branch for your change.
3. Make your changes.
4. Test the affected functionality.
5. Commit your changes with a clear commit message.
6. Open a Pull Request against the main repository.

Please keep Pull Requests focused on a single feature, bug fix, or logical change whenever possible.

## Reporting bugs

When reporting a bug, please include:

* a clear description of the problem;
* steps to reproduce it;
* expected behavior;
* actual behavior;
* browser and operating system when relevant; and
* screenshots or sample question files when useful.

Do not include credentials, private certification material, personal information, or other sensitive information in issues or Pull Requests.

## Proposing features

Feature proposals are welcome.

Please explain:

* what problem the feature solves;
* how you expect it to behave;
* whether it changes the question-bank format; and
* whether existing question banks would remain compatible.

For significant architectural changes, opening an issue before implementing the feature is recommended.

## Code contributions

Code should:

* remain readable and reasonably documented;
* avoid unnecessary dependencies;
* preserve accessibility where possible;
* work with the supported browsers;
* avoid introducing unnecessary external services; and
* preserve compatibility with existing question banks unless a breaking change has been explicitly accepted.

## Contributor License Agreement

CertifyLab uses a Contributor License Agreement (CLA).

Before a Pull Request containing a Contribution can be merged, the Contributor must accept the CLA contained in `CLA.md`.

You retain copyright ownership of your original Contributions.

The CLA grants the Project Maintainer additional rights to use and relicense accepted Contributions. This is necessary because CertifyLab may be distributed under more than one licensing model.

In particular, CertifyLab may have:

* an open-source edition distributed under AGPL-3.0; and
* separately licensed commercial or proprietary editions.

By accepting the CLA, You acknowledge that your Contributions may be incorporated into either or both.

You remain free to use and license your own original Contributions elsewhere.

Please read `CLA.md` before contributing.

## CLA acceptance

The repository may use an automated mechanism to record CLA acceptance.

When requested on a Pull Request, follow the instructions provided by the CLA check.

Do not indicate acceptance on behalf of another person.

Contributions cannot be merged until any required CLA acceptance has been recorded.

Any third-party code or assets must be clearly identified together with their source and license.

Do not submit proprietary code belonging to an employer, client, or other third party without authorization.

## Questions

If you are uncertain whether a proposed Contribution is compatible with the Project's licensing model, open an issue before submitting the code.
